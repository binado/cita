# ADR 0001: Source snapshots and generated bibliography

- Status: accepted
- Date: 2026-07-17

## Context

Using `references.bib` as both provider response and database made every record
implicitly INSPIRE-managed, coupled provider access to BibTeX parsing, and left
no durable provider identity for safe refreshes. Storing only a normalized
projection would lose exact provider BibTeX and provenance needed for review.

## Decision

`cita.toml` schema 2 is the sole authority. Each local citation key owns one
tagged provider snapshot. INSPIRE snapshots persist selected typed JSON plus raw
INSPIRE BibTeX; imported snapshots persist one exact standalone BibTeX entry.
Both implement a provider-neutral `ReferenceSource` projection.

`references.bib` is generated deterministically from snapshots. Preserved raw
entries are re-keyed by changing only the citation-key token. A future source
without raw BibTeX is rendered by constructing a `biblatex::Entry` and using its
serializer.

Every normal read verifies generated bytes. Mutations validate the full
candidate, write and sync the bibliography first, then write and sync the
manifest as the commit point. An interrupted second write leaves detectable
drift repairable with `cita generate`.

INSPIRE refreshes use stable record IDs. Imported snapshots are never refreshed.
Normalized DOI, arXiv, and namespaced provider identities must be unique across
all local keys and source kinds.

## Consequences

- Git reviews retain authoritative source changes and deterministic output.
- Local keys remain stable across provider texkey changes.
- Non-INSPIRE records can be stored without pretending INSPIRE owns them.
- A normal metadata edit must go through Cita, and hand edits to
  `references.bib` intentionally fail consistency checks.
- Schema 1 is a clean break with no automatic migration.
